What your client reads

Not a stack trace. A sentence.

When something is held, Gemma reads what code found and explains it twice: once for the shop owner, once for you. Code checks every word it writes for the owner: no jargon, no invented numbers, no promises nobody made.

How it works

Five promises, each kept by code.

The model explains. It never decides what happens to a message.

  1. 1

    Saved before anything else

    The moment a message arrives, Holdfast writes it to disk. Only then does it tell the sender "got it". If anything crashes after that, the message is still there.

  2. 2

    Checked at the door

    Every message carries a signature only the real sender can make. Anything that doesn't match, or is suspiciously old, is kept aside and never passed on.

    {{template "check"}} Signed by Stripe Signature didn't match

  3. 3

    Passed on, patiently

    If the app is down or busy, Holdfast waits a little longer each time and tries again. If the app says no for a reason a retry won't fix, it stops and holds the message.

    Try 1 · downTry 2 · downTry 3 · arrived

  4. 4

    Explained in plain words

    Code compares a failed message with the last one that worked and finds exactly what moved. Gemma turns that into a sentence for the owner and a fix for you.

    customer_id customer.id

  5. 5

    Sent again, never twice

    One button sends everything held, in the order it arrived. Anything already delivered, or that arrived twice, is left out, so a payment is never counted twice.

    Arrived Duplicate stopped

Why an open model

Your clients' payments stay with you.

  • Private. Messages carry names, addresses and amounts. Gemma runs on the same server as Holdfast, so none of it goes to an AI company.
  • Cheap to run. No bill per message. One small model on one server explains every failure.
  • Checked. The model picks from a fixed list of causes and code checks what it writes. If it gets something wrong, the built-in rules answer instead.

What's real today

Plainly, so you know what you're looking at.

  • GitHub, live. Sign in, pick a repository, and real webhooks flow through Holdfast.
  • Stripe, by hand. One-click Stripe sign-in needs a Stripe platform account, which this project doesn't have yet. You paste one address into Stripe and its signing secret into Holdfast instead.
  • The demo's customers are made up. The relay, retries, checks and explanations are the same code Live mode uses.
  • Explanations take a minute. Gemma runs on a small CPU server. You see the built-in rules' answer straight away, and Gemma's replaces it when it's ready.
