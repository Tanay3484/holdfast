What your client reads

Not a stack trace. A sentence.

When something is held, Gemma reads what code found and explains it twice: once for the shop owner, once for you. Code checks every word it writes for the owner: no jargon, no invented numbers, no promises nobody made.

How it works

Five promises, each kept by code.

The model explains. It never decides what happens to a message.

  1. 1Saved firstOn disk before "got it"
  2. 2CheckedForgeries kept aside
  3. 3Retried, then heldA down shop loses nothing
  4. 4ExplainedGemma, in plain words
  5. 5Sent again, onceDuplicates never get through

Why an open model

Your clients' payments stay with you.

  • Private. Messages carry names, addresses and amounts. Gemma runs on the same server as Holdfast, so none of it goes to an AI company.
  • Cheap to run. No bill per message. One small model on one server explains every failure.
  • Checked. The model picks from a fixed list of causes and code checks what it writes. If it gets something wrong, the built-in rules answer instead.

What's real today

No surprises.

  • GitHub is live. Real repos, real webhooks.
  • Stripe connects by hand. One-click sign-in needs a Stripe platform account we don't have yet.
  • Demo customers are made up. The engine is the same one Live uses.
  • Explanations take a minute. You see a rules answer instantly; Gemma's replaces it.
