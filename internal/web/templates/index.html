How it works

Five promises, each kept by code.

The model explains. It never decides what happens to a message.

  1. 1

    Saved before anything else

    The moment a message arrives, Holdfast writes it to disk. Only then does it tell the sender "got it". If anything crashes after that, the message is still there.

  2. 2

    Checked at the door

    {{if unlocked "signature"}}

    Every message carries a signature only the real sender can make. Holdfast checks it first. Anything that doesn't match is kept aside, never passed on.

    {{template "check"}} Signed by Stripe Signature didn't match

    {{else}}{{template "wip" (level "signature")}}{{end}}
  3. 3

    Passed on, patiently

    {{if unlocked "retries"}}

    If the app is down or busy, Holdfast waits a little longer each time and tries again. If the app says no for a reason a retry won't fix, it stops and holds the message instead of hammering away.

    Try 1 · downTry 2 · downTry 3 · arrived

    {{else}}{{template "wip" (level "retries")}}{{end}}
  4. 4

    Explained in plain words

    {{if unlocked "changes"}}

    Code compares a failed message with the last one that worked and finds exactly what moved. Gemma turns that into a sentence your client understands, and a fix for you.

    customer_id removed customer.id added

    {{else}}{{template "wip" (level "changes")}}{{end}}
  5. 5

    Sent again, never twice

    {{if unlocked "resend"}}

    Once it's fixed, one button sends everything held, in the order it arrived. Anything already delivered, or that arrived twice, is left out, so a payment is never counted twice.

    Arrived Duplicate stopped

    {{else}}{{template "wip" (level "resend")}}{{end}}

Why an open model

Your clients' payments stay with you.

  • Private. Messages carry names, addresses and amounts. Gemma runs on the same server as Holdfast, so none of it goes to an AI company.
  • Cheap to run. No bill per message. A small model on one server explains every failure.
  • Checked. The model picks from a fixed list of causes and code checks every word it writes for the client. If it gets something wrong, the built-in rules answer instead.
